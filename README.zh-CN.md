# LanGame Server Manager

[English](README.md) | [简体中文](README.zh-CN.md)

LanGame Server Manager 是一款 Windows 专用游戏服务器管理工具，可在桌面上完成安装、配置和日常管理。服务器文件、设置、日志和备份均保留在本机。

启用远程 AI 服务后，所需的对话与诊断上下文会发送给该服务。发送内容和脱敏边界详见 [AI 助手数据说明](docs/assistant.md#简体中文)。

可以在同一工作区管理一个联机世界或多台游戏服务器，使用游戏原生设置，并为每个实例分配独立的文件与端口。

## 主要功能

- 通过受支持的游戏模块安装和更新专用服务器。
- 创建独立实例，分别管理端口、原生配置和存档；游戏支持时共用服务器程序。
- 在同一桌面工作区内启动、停止、检查和备份服务器。
- 检查和操作 ARK 集群，在全组停服后创建一致快照并执行可回滚恢复。
- 为每个实例的完整进程组设置可选的 CPU 与提交内存上限。
- 关闭 Windows 窗口时隐藏到系统托盘，服务器继续运行；可从托盘恢复界面或安全停止运行服务。
- 查询玩家，并执行对应游戏支持的管理员操作。
- 通过可选 [AI 助手 **LAN**](docs/assistant.md#简体中文) 使用已配置的本地或远程模型服务。
- 通过 [LanGame 局域网目录协议 v2](docs/lan-directory-protocol-v2.md) 在局域网内发布有明确边界的只读运行状态。

## 支持的游戏与平台

[`modules/`](modules/) 目录包含 32 个专用服务器模块，涵盖幻兽帕鲁、Minecraft、Valheim、ARK: Survival Ascended、ARK: Survival Evolved、饥荒联机版、Rust、七日杀和僵尸毁灭工程等游戏。

可用的设置、查询和管理操作因游戏及服务器版本而异。已建模设置及其来源详见[服务器配置指南](docs/server-configuration.md#简体中文)和[游戏接入文档](docs/README.md#游戏接入)。

支持 Windows 桌面运行环境，安装包格式为 NSIS。界面提供英文和简体中文。

## 运行要求

应用在本机运行，无需 LanGame 账号或托管控制平面。LAN 为可选功能，模型服务的使用条件取决于所选服务。

安装和服务器实例分别管理。卸载后若没有已安装或可恢复的程序来源，须先安装服务器文件，再创建实例。首个已验证实例可以直接使用尚未被使用的已下载安装，不移动目录、不额外复制程序。新增独立实例只复制已验证的程序文件并独立保存数据；Minecraft 原版还支持明确选择共享程序。创建服务器统一使用干净原版和新的配置、存档；现有文件无法通过核验时，会在独立库目录复用可验证的文件、从官方补齐缺失内容，然后自动继续创建。修复后的库在删除全部实例后仍然保留；独立实例使用自己的程序副本，运行时不会修改这份保留来源。原有安装、修改、实例和归档保持不变。准备过程支持取消；中断的获取保留文件和登记，后续尝试只复用能够核验的文件。

受支持的 SteamCMD 和 Minecraft Java 安装默认在每次实例启动前检查更新。更新针对该实例实际使用的程序目录，完成后才生成配置并启动进程。在实例维护中选择“保留当前版本”，可关闭自动更新，并阻止商店和维护入口修改这份程序，直到解除固定；共享程序的任一引用实例固定版本时，整份程序受到保护。只读检查确认 Minecraft 发布版本和 Java 运行时符合要求时，其他共享实例可继续启动。检查失败，或必要更新被运行实例、归档依赖阻止时，启动会停止并说明原因。整包替换型安装源继续通过手动维护处理。

创建时会核验选中的程序文件，在支持的文件系统上复用已验证的文件身份，避免重读未改变的内容。最后一个实例永久删除后，原库没有实例或归档占用、程序完整且没有旧配置、存档或 Mods 残留时，可以再次原位使用。空目录和正常删除时移除的原版默认配置不会强制产生程序副本。未知或修改过的文件保留，创建改用经过验证的独立副本；明确保留为修复来源的库继续保持来源用途。已验证的本地程序完整时无需下载或占用 SteamCMD，其他游戏的下载可以与创建并行进行。

删除实例会清除其拥有的数据和实例专属程序副本，用户保留的安装仍在游戏库可见；无法确认归属的文件和外部存档继续保留。数据归档保存个人文件及修改，恢复依赖精确匹配的程序源，更新和卸载不得使此依赖失效；缺少可靠重建来源时，完整归档保留程序字节。已有归档继续保有原来的恢复能力。

在软件外删除已停止实例的整个托管目录后，刷新服务器列表会自动清除残留记录，不改动游戏库和外部存档。实例专属程序文件缺失时，实例继续保留并可手动删除；存储位置不可访问或实例仍在运行时不会自动清除。

游戏库卸载要求该游戏的实例均已停止。它清理未被引用的库安装及已登记变体，保留实例专属程序副本。首实例原位引用、共享实例或归档仍依赖的库程序会保留并说明原因；卸载不会自动拆分这些引用。

同一游戏或不同游戏的实例可以同时运行，文件与受管端口分别管理；CPU、内存、磁盘和网络容量仍由整台主机共享，这不构成安全容器。端口组、ARK 共享传输目录、资源限制与主动停止运行服务的说明见[服务器配置指南](docs/server-configuration.md#简体中文)。

不同游戏对硬件、存储、网络和专用服务器运行环境的要求不同，安装前应查阅对应游戏文档。本仓库不分发专用服务器二进制文件、专有游戏文件或未经批准的第三方媒体。游戏名称和商标归各自权利人所有。

## 从源码运行

请先安装以下环境：

- Git。
- 带 MSVC 目标的 Rust `1.98.1`。仓库通过 `rust-toolchain.toml` 固定工具链版本。
- 带 npm `>=11.16.0` 的 Node.js `^22.22.2` 或 `>=24.15.0`。推荐使用 CI 同款的 Node.js 24 LTS。
- Microsoft C++ Build Tools 和 Microsoft Edge WebView2；安装方法见官方 [Tauri 前置条件](https://v2.tauri.app/start/prerequisites/)。
- Python 3.11 或更高版本，用于执行仓库校验脚本。

在仓库根目录安装前端依赖，并在不改写锁文件的前提下检查 Rust 工作区：

```powershell
npm ci --prefix apps/desktop --strict-allow-scripts
npm --prefix apps/desktop run build
cargo check --workspace --locked
```

启动前端开发服务器：

```powershell
npm --prefix apps/desktop run dev
```

在第二个终端启动桌面进程：

```powershell
cargo run --locked --manifest-path apps/desktop/src-tauri/Cargo.toml --bin langame-desktop
```

如需在没有发行凭据的情况下生成本地 NSIS 安装包，请使用固定版本的 Tauri CLI。默认配置关闭更新签名产物和联网更新检查。`--locked` 会传递给底层 Cargo 构建。

```powershell
cargo install tauri-cli --version "=2.11.4" --locked
Push-Location apps/desktop
try {
    cargo tauri build -- --locked
    if ($LASTEXITCODE -ne 0) { throw "Tauri build failed." }
}
finally {
    Pop-Location
}
```

安装向导支持英文和简体中文，按当前用户安装，并注册 Windows 卸载入口。安装包内置微软官方 WebView2 离线安装程序，缺少运行时的电脑无需在安装时临时下载，已有运行时会直接复用；构建安装包时仍须访问微软运行时下载服务。手动安装或卸载前，请从系统托盘选择**退出**，等待服务器停止。卸载应用会保留服务器文件和设置；可选的界面数据清理不等于完整擦除数据。

维护者可用 [`scripts/build_desktop_update_artifacts.ps1`](scripts/build_desktop_update_artifacts.ps1) 准备本地发行计划，必须显式将 `-OutputRoot` 指向仓库外的目录。默认无需签名密钥，不构建、上传或发布。托管工作站可用 `-BuildManaged` 从源码快照构建本地安装包并导出产物回执，默认关闭更新检查且无需更新私钥；签名构建和 GitHub 更新检查均需显式启用，详见[桌面发行指南](docs/desktop-release.md)。私钥和密码必须保留在仓库外。发现新版本后自动提示，直接选择前往下载或在线更新；只有明确准备的启用版本才会检查更新。

首次构建会下载 Rust 与 npm 依赖。只有运维人员启动对应游戏流程时，应用才会获取专用服务器程序包。

## 问题反馈

请使用仓库提供的 Issue 表单报告可复现缺陷、范围明确的功能建议或 Windows 专用游戏服务器接入需求。提交 Issue 或 Pull Request 前，必须删除凭据、私有地址、玩家数据、专有文件和未经许可的媒体。

游戏服务器或模组自身的问题，请先查阅其发行方文档和支持渠道。如果问题涉及本应用的安装、配置生成或进程管理，请在缺陷报告中提供游戏模块和复现步骤。

安全漏洞应通过 [SECURITY.md](SECURITY.md#简体中文) 中的私下流程报告。
