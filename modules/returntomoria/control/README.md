# Native current-world save

Manual save calls the reflected `/Script/Moria.MorUIFunctionLibrary:SaveCurrentWorld(WorldContext)` once on EngineTick. The exact UFunction flags and its `WorldContext` ObjectProperty are checked before invocation. The game resolves its own manager and calls `AutoSaveAsync`; `CanSaveWorldState` owns native initialization, enabled, idle, authority, restoration and writable-world checks. LanGame does not read those private fields or call a fixed native address.

A returned void call is reported as `save_completion=requested`, with no disk-completion claim. The native API may decline a request according to its own state. An exception, missing acknowledgment or expired request remains unknown and is not resent. The adapter requires the unique authoritative begun-play world, its owning game instance, the current manager/world-state ownership and reflected `bAutoSaveEnabled`; it never enables autosave or changes the game's policy.

The host pins and verifies the supported game image and official UE4SS loader. Each managed launch inherits a fresh session token; requests bind that token, nonce, boot and current world. The exact managed process tree and Shipping creation identity are checked throughout the exchange. The host worker retains the instance mutation reservation and storage lease even if its caller is cancelled.

Stopped startup bundles this policy with `apps/desktop/src-tauri/src/live_players/unreal_save_protocol.lua` and publishes the owned `Scripts/main.lua` and `enabled.txt` using the existing recoverable ownership record. The replaced `native/LgsmMoriaSaveControl.dll` is retired only when its current bytes match that record. Unknown or modified files are preserved and reported. The verified UE4SS `3.0.1-1125-g527a483b` loader and its `dwmapi.dll` proxy have separate ownership and are retained.

The reflected call contract was established from Steam build **21872765** and its matching PDB (Shipping SHA-256 `4513fb58ca31a3c7c7640ebeff9717ef68776b922986036f0c5b325dd28255fb`): `SaveCurrentWorld` has flags `0x4022401` and one `WorldContext` ObjectProperty, and routes through `MorSaveGameManager::Get`, `AutoSaveAsync` and `CanSaveWorldState`. The Lua fixtures exercise the bundled policy, session/world boundaries, one call, no replay and unknown outcomes. They do not establish real disk persistence; native acceptance must retain a pre-stop snapshot and independently reload it.

## Normal shutdown

Normal shutdown remains a separate `moria_console` path. It sends the publisher's native `exit` command once to the uniquely owned Shipping console; it is never used for manual saving. A bounded private helper verifies the tracked Job, image and process generation. The helper itself belongs to a separate kill-on-close Job so manager loss reclaims it.

Build 21872765 can reach `FEngineLoop::Exit` while its console input thread remains blocked in `ReadConsoleW`, preventing `FreeConsole` from completing. The existing shutdown profile verifies the exact image and native exit-state transition before requesting `CancelSynchronousIo` once for the uniquely named `MorDedicatedServerConsole::InputThread`. It does not write game memory, terminate a thread or resend `exit`. API success alone is insufficient: the supervisor still requires the complete owned process tree to exit normally. The 12-second helper deadline, module wait and final grace retain their existing bounds. This targeted shutdown compatibility code is independent of the removed save bridge.
