# Native current-world save

Manual save calls the reflected `/Script/Moria.MorUIFunctionLibrary:SaveCurrentWorld(WorldContext)` once on EngineTick. The exact UFunction flags and its `WorldContext` ObjectProperty are checked before invocation. The game resolves its own manager and calls `AutoSaveAsync`; `CanSaveWorldState` owns native initialization, enabled, idle, authority, restoration and writable-world checks. LanGame does not read those private fields or call a fixed native address.

A returned void call is reported as `save_completion=requested`, with no disk-completion claim. The native API may decline a request according to its own state. An exception, missing acknowledgment or expired request remains unknown and is not resent. The adapter requires the unique authoritative begun-play world, its owning game instance, the current manager/world-state ownership and reflected `bAutoSaveEnabled`; it never enables autosave or changes the game's policy.

The host pins and verifies the supported game image and official UE4SS loader. Each managed launch inherits a fresh session token; requests bind that token, nonce, boot and current world. The exact managed process tree and Shipping creation identity are checked throughout the exchange. The host worker retains the instance mutation reservation and storage lease even if its caller is cancelled.

Stopped startup bundles this policy with `apps/desktop/src-tauri/src/live_players/unreal_save_protocol.lua` and publishes the owned `Scripts/main.lua` and `enabled.txt` using the existing recoverable ownership record. Startup retires the replaced `native/LgsmMoriaSaveControl.dll` independently of current game or loader compatibility, and only when its current bytes match that record. Unknown or modified files are preserved and block startup. The ownership receipt is retained for recovery. On unsupported builds, the separately owned UE4SS proxy is deactivated after its ownership and remaining mods are verified; the game can then start without manual save support.

The reflected call contract was established from Steam build **21872765** and its matching PDB (Shipping SHA-256 `4513fb58ca31a3c7c7640ebeff9717ef68776b922986036f0c5b325dd28255fb`): `SaveCurrentWorld` has flags `0x4022401` and one `WorldContext` ObjectProperty, and routes through `MorSaveGameManager::Get`, `AutoSaveAsync` and `CanSaveWorldState`. The Lua fixtures exercise the bundled policy, session/world boundaries, one call, no replay and unknown outcomes. They do not establish real disk persistence; native acceptance must retain a pre-stop snapshot and independently reload it.

## Normal shutdown

Normal shutdown remains a separate `moria_console` path. It sends the publisher's native `exit` command once to the uniquely owned Shipping console; it is never used for manual saving. A bounded private helper verifies the tracked Job, image and process generation. The helper itself belongs to a separate kill-on-close Job so manager loss reclaims it.

Native exit delivery does not require a supported manual-save build or a fixed-address shutdown profile. The helper verifies the current Shipping image path and process identity, an empty native command prompt and the complete console membership before writing `exit` once. Retained kernel handles keep those process objects pinned; repeated image-path queries are unnecessary and can fail during teardown before the handles become signaled. Live Job membership and console membership remain mandatory.

After the fresh native exit response, the helper may supply a bounded empty line to the uniquely named, owned input thread at each new empty prompt. A successful empty read passes through the game's own stop check without executing another console command. There are at most 32 wakeups within the existing 12-second helper budget, paced across its remaining time. Each requires a fresh prompt transition, no pending input, pending thread I/O, unchanged ownership and a final deadline check. A detached console or naturally ended input thread stops further writes. This never proves a save completed: `native_exit_queued` confirms only delivery, and even `native_process_exited` still requires the supervisor to observe the complete owned Job exiting normally.

The previous fixed-RVA exit-state inspection remains removed. `CancelSynchronousIo` is also excluded: a self-owned console probe on Windows 10.0.26100.9278 reproduced `ReadConsoleW` returning TRUE after cancellation while retaining the prior character count and input buffer, which could replay the old command. No console-close signal, thread termination or automatic process termination substitutes for normal exit. Failure retains ownership and reports the timeout without replaying `exit`.

On 2026-10-23, fresh disposable copies of build **21872765** with no UE4SS proxy, loader or save bridge reproduced a native shutdown stall. Separate instances received either one `exit` command or one `CTRL_C_EVENT` through the existing verified-console transport. Both remained alive beyond the unchanged 27-second stop budget and a further 120-second read-only diagnostic observation. The Ctrl-C case logged `AMorPauseManager::PrepareToLeaveGame` and `HandlePlayerLeavingGame: initiate, server`, proving that the signal reached the native shutdown path. The bootstrap waited for Shipping; Windows wait-chain inspection reported the Shipping primary thread and `MorDedicatedServerConsole::InputThread` blocked, but did not establish their complete dependency chain. This evidence does not establish a loader fault or a verified general workaround. The publisher documents Ctrl-C as save-and-quit; this build's observed result remains an unsuccessful normal stop. Test cleanup of the disposable process tree is not counted as native shutdown success.

The Ctrl-C result covers `GenerateConsoleCtrlEvent`, not a terminal keyboard event or ConPTY input byte `0x03`. The current `console_ctrl_c` transport uses the same event API for ConPTY-hosted processes; managed terminal line input rejects control characters. Existing console-handler tests establish event receipt, not release of a blocked `ReadConsole`. Changing only the host surface would not test that distinct input behavior.

The opt-in `native_moria_no_loader_shutdown_control` test keeps the native transport separately reproducible without changing production startup. It requires `LANGAME_NATIVE_MORIA_NO_LOADER_CONTROL=true`; `LANGAME_NATIVE_MORIA_CONTROL_TRANSPORT=exit` (default) or `ctrl_c` selects exactly one request on a fresh fixture. Its 27-second budget includes delivery. A fresh no-loader instance with the empty-input wakeup completed the whole Job naturally in 4.626 seconds with exit code 0. Save/restart, backup restore and archive restore remain separate acceptance phases; this transport-only result does not establish persistence.

The full persistence fixture opts into `native-test-console` to query native difficulty and change Normal to Hard once. Creation configuration remains Normal. It captures the formal save before shutdown, restores that checkpoint, and queries Hard from a different owned process before any new save or difficulty change. Backup and archive restoration use the same content oracle. Test-only commands and timing observations do not change the production `Requested` receipt or grant arbitrary console access.

The complete build **21872765** fixture passed on 2026-10-23: four normal whole-Job exits with code 0, plus native Hard readback after restart, backup restoration and archive restoration. The pre-stop checkpoint was captured at Shipping age 24.503 seconds, before the observed 300-second native autosave interval; it contained world `MW_B1A20BF6454AD9AA389F49AE4D9442FA.sav` with SHA-256 `6d034713ecd0ed3295128eb3cc0c2a15f50aec72728e34224a80c84809f3f263`. Each readback preceded the next save. Archive restoration also recovered from an injected database COMMIT failure while preserving the stopped native permissions roster, configuration, world and program. The fixture finished with no owned processes, bound ports or remaining scratch entries. This establishes persistence and normal shutdown for that verified build, not network update or GUI acceptance.

The isolated case directory and original native evidence were subsequently removed with other acceptance batches; the user confirmed a separate cleanup. The successful exit and content checks had already been read through tool outputs, but the original logs and checkpoint are no longer available. See the [lifecycle acceptance record](../../../docs/runtime-lifecycle.md) for the evidence-retention limitation; this run cannot serve as a complete retained release evidence bundle.
