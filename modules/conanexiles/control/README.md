# Current-world native save

Starting the instance automatically prepares its independent runtime, installs and configures the fixed official UE4SS **3.0.1-1125-g527a483b**, a correctly generated genuine upstream **DSOUND proxy**, and the owned `LgsmWorldSave` policy and native bridge before creating the game process. This Shipping image imports `DSOUND.dll`; it does not import the default DWM proxy or the version proxy. Renaming a DLL does not supply the required exports. The generated proxy is bundled with LanGame; users need no native build tools. Archive/core/proxy hashes are checked and required [native-save settings](UE4SS-settings.ini) are merged while preserving unrelated fields, comments and existing Mods. A compatible verified loader can be reused; ambiguous entries, unknown core/proxy files and externally edited owned files are preserved and reported as conflicts. Owned interrupted publication can resume. Shared program files remain untouched. The private mod contains `Scripts/main.lua`, `enabled.txt` and `native/LgsmConanSaveControl.dll` plus its ownership marker.

The loader also installs the unmodified [Conan UE 5.8 virtual-function layout](VTableLayout.ini) from [UE4SS commit `b0d470ba0ff2cb9ba1832b7b9fad01a1cd4fc1a6`](https://github.com/UE4SS-RE/RE-UE4SS/blob/b0d470ba0ff2cb9ba1832b7b9fad01a1cd4fc1a6/assets/CustomGameConfigs/Conan%20Exiles%20Enhanced/VTableLayout.ini), SHA-256 `20bd7529e536c9267b60f8b13990785401bf3cb4c091d2f59dd94105ccba2c10`. All admitted executable/provider pairs use that layout; other modules retain their own profiles. The required settings explicitly select engine version 5.8 before the loader parses the layout. In this pinned UE4SS build, parsing precedes automatic engine detection; leaving the override unset incorrectly gives `FProperty` the older `UField` inheritance. A conflicting operator version override is preserved and reported. Conan's additional `FProperty` virtual function shifts `GetMinAlignment` to slot 46. Without this layout, UE4SS calls slot 45, receives a pointer instead of an alignment, and may abort initialization depending on the loaded address. The upstream [intermittent-initialization fix](https://github.com/UE4SS-RE/RE-UE4SS/commit/3fe752355dd240e09e50c6e4ad4524053da555c7) and subsequent 5.8 layout update cover this distinction. The layout is installed before proxy activation and is tracked by the existing ownership receipt. An earlier complete owned runtime can gain the missing layout; unknown or externally edited layout files are preserved as conflicts. Upstream [MIT terms](LICENSE-UE4SS.txt) apply to this file.

The native bridge verifies actual loaded-module paths, pins/hashes these files and rejects a changed contract. It calls the whole-world persistence component, not the reflected **CharacterPersistenceComponent.ForceSave** method.

Extra trailing text, partial world states and server-name echoes remain invalid.

The policy initializes the pinned UE4SS EngineTick dispatcher during mod loading with one empty callback. The fixed upstream [lazy hook registration](https://github.com/UE4SS-RE/RE-UE4SS/blob/527a483b63b4dd0104fe1ca1a3934a06b87fcfb2/UE4SS/src/Mod/LuaMod.cpp#L4169) runs synchronously on the first dispatch and can outlast the short request queue deadline. Initialization reads no world, publishes no request and calls no native save; the existing request deadlines, world checks and no-resend behavior remain unchanged.

During mod loading, a separate request-free native entry verifies and pins the complete executable, fixed loader and paired Dreamworld provider. It checks the already loaded module paths and fixed code/export guards, without reading a request, looking up a world or calling a save. The cached result is reused; failed preparation leaves the native contract unavailable. This keeps static file hashing outside the short request deadline.

UObject lookup, native probes, saves and completion observations run only on EngineTick. The authenticated protocol selects the unique server GameNetDriver and retains its begun-play world, game mode, game state, owning game instance and exact persistence component. The bridge rechecks the fixed class, owner/world, weak owner and ready database before entry. Process-only launch identity, current managed/native PID and creation identity, boot/world tokens, closed request fields, short deadlines and a bounded native replay table prevent stale or duplicate dispatch. An unknown native receipt is written before the one native entry. There is no automatic resend after any timeout, exception or incomplete receipt. Optional Conan probe diagnostics contain only closed stage/phase labels, emit at most eight lines per probe and never participate in readiness or completion.

Queue admission uses the fixed loader's [steady-clock delayed-action elapsed time](https://github.com/UE4SS-RE/RE-UE4SS/blob/527a483b63b4dd0104fe1ca1a3934a06b87fcfb2/UE4SS/src/Mod/LuaMod.cpp#L5361), with the existing 3000 ms budget. Integer Unix seconds remain the request-freshness and receipt timestamps; they no longer measure queue duration, which could previously expire after only two to three actual seconds. Each dispatch, including a completion poll, owns a separate timer budget. Its sentinel only marks that budget expired and cannot cancel a later request or poll. A missing/retired timer rejects admission. All world lookup and native request handling still require EngineTick; already-entered native work retains its original 30-second completion limit.

The current adapter observes the original native job without invoking another save. It confirms only after receiving every unique native result index from zero through the final statement, with at least the BEGIN/END statements and successful status for every statement. Native aggregate mode also requires its complete owned result and all successful statuses. Any SQL error reports failure only after that owned sequence settles. A missing, malformed, duplicate, late or mismatched callback remains unknown. No file timestamp, shared autosave event or bare void return can confirm this request. This contract covers the world's native pending persistent-actor transaction; it does not claim a hardware fsync or serialize unrelated game state.

Every pending poll republishes the exact original nonce, operation, timestamp and world/component addresses. The native replay cache observes that job only, rejects changed keys and retains unexpired entries under saturation. The overall deadline is also bounded by a monotonic clock. One outstanding job remains busy after a timeout or world change until its actual callbacks settle; expiry never cancels a job or permits its callback storage to be freed. Callback modules are pinned for process lifetime and the one bounded state survives Lua cancellation. Existing shutdown, backup and moderation behavior are separate.

## Native acceptance

On 2026-11-16, build **26672347** passed the strict manual-save acceptance and a separate four-cycle standard lifecycle on the same immutable manager build. The strict run confirmed one owned SQL save, restored the exact pre-stop SQLite checkpoint after normal shutdown and loaded it in a fresh process without a second save; both processes exited with code zero. The standard lifecycle confirmed four saves and four normal exits, restored 13 backup files, preserved 16 save files and one native config during library uninstall, and recovered an interrupted archive commit. The final records bind all source files, the test binary, full logs and zero-process cleanup. Earlier failed trials and partial successes remain recorded in the [2026-11-16 contract and acceptance record](../reference-fixtures/2026-11-16-native_contract_build_26672347.json).

On 2026-11-14, build **26552396** passed two separate existing native acceptance entries on an isolated Windows host. The strict `native_manual_save` run confirmed its original native SQL completion, captured the exact SQLite checkpoint before stopping, restored it after normal shutdown and loaded it in a fresh process without sending another save. Both processes exited normally with code zero. The standard `native_package_lifecycle` run completed four normal startup/save/stop cycles, verified 13 restored backup files, retained 15 save files and one native config during library uninstall, and recovered an interrupted archive commit. All four save requests received native SQL completion confirmation. See the [current contract and acceptance record](../reference-fixtures/2026-11-14-native_contract_build_26552396.json).

These were new empty-player worlds. The strict manual checkpoint readback and standard file-level backup/archive recovery have distinct scopes: content-level identity of a backup-restored Conan world remains unsupported by the optional restored-world verifier. The earlier combined trial stopped at that explicit boundary and remains recorded as failed. No assertion or profile allowlist was weakened, and no populated-player/building migration, GUI or multiplayer acceptance is claimed.

The following is historical admission-only evidence, before the owned SQL completion adapter. On 2026-10-19 a normal task-owned program copy excluded all original Saved data, Steam configuration/cache/logs and application ownership metadata. It used a new private world and loopback bind arguments. The genuine upstream proxy was built from the 32 hash-checked source files at fixed UE4SS commit `527a483b63b4dd0104fe1ca1a3934a06b87fcfb2`; the local system DSOUND DLL's signature was checked before generating its 12 forwarding exports. CMake and native link succeeded. The tested proxy SHA-256 was `e0066aeb6abad295ee5f27a5da06254c00859058f8babfdaf2dfc78e922312d0`. No injector or system DLL replacement was used.

Normal startup loaded that proxy, the fixed loader and production payload. The current native database reached ready state; production saveprobe returned ready. **One** authenticated save request returned `invoked=true`, `call_returned=true`, `write_confirmed=false`, with a matching native `returned` receipt and no crash. The new world's `game_0.db` and native WAL were readable after the process was reclaimed; SQLite `quick_check` returned `ok`, with 16 native actor-position and 16 game-event records. No client/constructed character or building was imported, and the initial world had zero loaded mutable persistent actors.

A separate startup of the same private Saved directory loaded the native database, completed `WorldPersistenceDone`, and reached the unchanged production saveprobe ready state. No second save request was sent. Both trials ended with zero task-owned processes remaining. This proved the actual native whole-world flush entry and database reopen in an empty-world fixture; it did not prove a populated-player/building reload or per-request completion.

The strict `/W4 /WX` native build and malformed-request tests cover both adapters. The deterministic Lua fixture executes the actual policy and production protocol, including wrong owner/class, changed worlds, client/ambiguous drivers, replay, nonce/PID mismatches and deadline races. It mocks external boundaries and is not substituted for the native trial.
