# Native manual save over RCON

The declared `save_world` action uses HumanitZ's documented `save` command. New instances enable the native RCON interface with their own generated secret. Existing explicit `rcon_enabled=false` is preserved; that instance must enable its management interface before the action is available.

HumanitZ has a different save-response contract from the generic Source RCON completion exchange. The dedicated save adapter sends authentication with request ID `0`, type `3`; it accepts the observed optional ID `0`/type `0` frame followed by ID `0`/type `2` authentication. After authentication, it sends exactly one ID `0`/type `2` `save` request. Only ID `1`, type `0`, and the exact UTF-8 body `Game saved!` acknowledge this operation. It sends no empty Source completion marker and never retries an unknown save. Wrong authentication, malformed or oversized frames, a different acknowledgement, EOF, partial writes and timeouts remain errors.

The response is a native acknowledgement. A successful submission returns `save_completion=requested`, displayed as a sent save request that the game executes. It does not establish synchronous disk completion, power-loss durability or save-content readback. Saving does not install UE4SS or a writer observer; existing Mod and loader configuration is retained. The existing read-only `humanitz_rcon` player-info transport remains restricted to `info`.

On 2026-10-19, a new isolated world from the current local Steam app `2728330`, build `23914958`, passed the production manager's strict game-endpoint, EOS-session and complete native-info readiness checks. Read-only player counts returned zero. A separate diagnostic then authenticated using the shipped `RCON_Utility/HMZ RCON.exe` framing and sent `save` once; the current native server returned ID `1`/type `0` and `Game saved!`. Normal manager stop and owned process cleanup passed. This protocol diagnostic is separate from acceptance through the formal manual-save action and does not claim persisted-content readback.

The tested Shipping executable SHA-256 was `c3f46f78220605e7a73151261b9bdb072786170dc0edc8c75da4ed872d67671a`. The shipped `RCONCommands.txt` supplies the command spelling. Read-only IL inspection of the bundled utility confirmed ID `0` command framing and its asynchronous response reader; the utility itself was not executed. The former generic Source exchange required response ID `14002`, ignored the actual native ID `1` response and timed out before sending its completion marker. Increasing a timeout cannot correct that mismatch.
