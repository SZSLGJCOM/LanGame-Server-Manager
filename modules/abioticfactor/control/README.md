# Native current-world save

Manual save calls the reflected `/Script/AbioticFactor.SaveCurrentWorld:SaveCurrentWorld(WorldContextObject)` factory once, then invokes the returned action's native `BlueprintAsyncActionBase:Activate` once on EngineTick. The game owns busy checks and its world save queue. LanGame does not read private queue, completion-handle or success-byte offsets, and does not replace the native save worker.

A returned `Activate` call is reported as `save_completion=requested`, without claiming that the game accepted or completed a durable write. The native entry can decline a request when the game is already saving or has no pending data. Its standard worker also ignores the underlying `SaveDataToSlot` Boolean, so observing its private success flag would not prove persistence. Exceptions, stale world/session identities and missing acknowledgments remain errors or unknown outcomes; the request is not resent.

The adapter requires one authoritative begun-play world, its owning Abiotic game instance and world-owned `SaveQueueSubsystem`, and a nonempty reflected `ActiveWorldSaveName`. It validates the factory and Activate signatures, then rechecks the original world and deadline between creating and activating the action. A waiting no-client world is rejected before invocation. Production code does not call `StartMatch`, change readiness, request a backup or stop the server.

The host pins and verifies the supported image and official UE4SS loader. Requests bind the fresh inherited launch token, nonce, boot and world identity. The managed process tree and exact Shipping creation identity are checked throughout the exchange. A cancelled caller does not release the worker's instance mutation reservation or storage lease early.

Stopped startup bundles the policy with `apps/desktop/src-tauri/src/live_players/unreal_save_protocol.lua` and publishes only the owned `Scripts/main.lua` and `enabled.txt`. Existing owned files are refreshed with recoverable compare-and-swap publication; external changes are preserved and reported. UE4SS `3.0.1-1125-g527a483b` and the upstream `version.dll` proxy have separate ownership. The game imports `VERSION.dll`, so the configured proxy remains necessary; no native save DLL is added.

The contract was established from Steam build **24343458** and its matching PDB (Shipping SHA-256 `2563f8d798c8277400acd28eefde604c0ac7d77601627296211af48b30dba25f`). Native code checks saving and pending data before queueing or starting its worker.

The same image reads `-ModsDir`, `-SideloadModsPath`, `-SteamServerName`, `-WorldSaveName`, `-ServerPassword` and `-AdminPassword` from the raw Windows command line using `FParse::Value`. Its parser skips parameter names inside quotes and stops unquoted values at spaces, commas and right parentheses. The Windows serializer therefore quotes only these verified options' values, preserving the canonical argument list. The native parser copies backslashes literally, including before a closing quote, so the Abiotic serializer does not use CRT backslash escaping. Password whitespace is retained. Embedded double quotes are rejected in the configuration UI and backend launch validation because the native parser ends the value at the first quote; explicit world names must remain one non-empty Windows directory name. Missing fields retain the existing schema default source. Stored empty world names are rejected without rewriting their value or moving existing data. The [Mod path trace](../reference-fixtures/2026-10-27-fparse_mod_paths_build_26092453.json) and [room/credential trace](../reference-fixtures/2026-10-27-fparse_room_values_build_26092453.json) record the matching image, individual consumers and parser limits. These static traces do not claim a downloaded or mounted Mod or a successful client join.

The guest and its temporary rules were reclaimed. This establishes anonymous download/mount and startup, without claiming token-backed cache behavior, sideloading, ordinary-permission SDK operation or client gameplay.

Lua fixtures exercise the real bundled policy, single factory/activation, no replay, world replacement, late callbacks and unknown results. Two isolated host runs of build26092453 also confirmed no-client rejection before invoking a save and fresh managed startup after stop. A no-client startup rejection is not a successful save test. Ready-world persistence acceptance requires a real native save, a pre-stop snapshot and independent restart readback; older offset-observer trials do not establish the revised adapter's behavior.
